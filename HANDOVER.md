Both `hfu/stars` PRs ([`#9`](https://github.com/hfu/stars/pull/9) GAEZ, [`#10`](https://github.com/hfu/stars/pull/10) HIH DR Congo) are merged and Martin is serving all 16 PMTiles sources plus the 7 GeoJSON final-location files — this is not a local-only prototype anymore, it's a working public demo. hfu approved the push-to-origin and Pages-enablement step explicitly (2026-09-03).
- **The client (`docs/index.html` + `docs/narrative.js`, `docs/map_intent.js`, `docs/aez_legend.js`, `docs/aez57_legend.js`, `docs/score_probe.js`) is a real, tested MapLibre app**, not a sketch: globe projection (motivated by the Togo/AU Mercator-bias UNGA resolution), Positron basemap with data layers correctly sandwiched below water/roads/boundaries/labels but above land-color fills, a checkbox panel across four raster groups (GAEZ, HIH score, accessibility, fishfarm) plus a vector "final sites" group, a cursor/pan-anchored score-comparison panel (`score_probe.js`), dynamic AEZ33/AEZ57 legends that sample the actual rendered pixel under the screen center, and — newest (D23) — a pulsing gold glow marker on each active "final" site, since each is one real FAO-selected location out of a whole raster of scored candidates and deserved to visually stand out rather than blend into the flat fill treatment every other layer gets.
- **Narrative playback and Map Intent are both implemented and spec-reconciled, not just prototyped.** `docs/narrative.js` (renamed 2026-09-05 from `story.js` — "narrative" is this project's settled term, D37) plays a hand-authored, real-finding-based 4-step, 10-language narrative (`SAMPLE_NARRATIVE`, also published as `NARRATIVES.md`'s first library entry, `samples/narrative-cod-maize-mystery.json` — the DR Congo maize-vs-actual-selected-site mystery, D13's finding) via `flyTo` + synced checkboxes + a caption panel; `map_intent.js` implements `staccato-spec`'s actual normative Map Intent format (YAML, `map-intent/v2`, single `render_hints` camera state — see `DECISIONS.md` **D19/D20** for the reconciliation against this session's earlier, spec-divergent design) via a paste-box (the required baseline) plus an optional URL-fragment path per **ADR 0004**. **D21/D22 found and fixed a real ADR-0004 compliance bug**: MapLibre's built-in `hash:"map"` option was silently re-injecting a cleared fragment payload on every map move, defeating the one-shot "read once, clear via `history.replaceState`" guarantee entirely — removed outright (no session-scoped `sharing_policy.url_share` toggle exists yet, so "no reflection at all" is the correct ADR-0005-compliant interim default), which also exposed and fixed a second latent regex bug in both files. Verified end-to-end, not just reasoned about — see D22 for the actual test sequence.
- **SUPERSEDED, see D34: Staff is now actually built.** (This bullet originally said Staff "still doesn't exist as running code" and assumed it needed one — that was wrong.) hfu corrected the mental model: Staff's implementation IS the system prompt, run inside any general-purpose AI chat agent — no backend, no API-calling code needed, ever. `STAFF-PROMPT.md` v0.2 (D33) is built around `#q=` (D32), a plain hand-typeable URL hand-off designed by directly consulting `dwg7/chukei`'s real working implementation of the same pattern. - **Real, working PMTiles/GeoJSON files exist and are live** (see above): `gaez-aez33.pmtiles`, `gaez-aez57.pmtiles`, `hih-cod-maize-score.pmtiles`, `hih-cod-maize-final.geojson`, and 19 more. The full COG→PMTiles pipeline (official-colormap-or-own-ramp → GDAL color-table VRT → MBTiles with forced `RESAMPLING=NEAREST` at every step → `gdaladdo` pyramid → `pmtiles convert`) is validated end-to-end. See `DECISIONS.md` **D7–D11** for the full trail of gotchas found along the way (GDAL's MBTiles driver needs an explicit overview pass or it writes only one zoom level; resampling defaults must be pinned to nearest-neighbor at *every* step, not just the pyramid step, or categorical/discrete data silently corrupts; WebP has no true-lossless option in GDAL's writer, disqualifying it for this data regardless of size).
- **HIH's two data shapes need two different treatments, discovered by actually inspecting the real COGs, not assuming from STAC metadata**: `LOCATIONSCORE`/`SCORE` layers are continuous Float32 with a *hidden* `-9999` sentinel value on top of the declared NoData (about half of "valid" pixels in the one checked so far) — must be masked and given a fixed 0–100 domain, not a per-file auto-stretch. `FINALLOCATION` layers are near-binary Int16 with only a tiny handful of real "selected site" pixels (417 of ~18M in the one checked) — too sparse for raster tiling to survive downsampling, so these are being converted to **vector** (GeoJSON polygons via `gdal_polygonize.py`), not PMTiles, reversing D9's original all-raster assumption. Full detail in `DECISIONS.md` **D10**.
- **Client-map design decisions are set, implementation not yet done**: MapLibre **globe projection**, not flat Mercator — directly motivated by Togo's African-Union-backed resolution going to a UN General Assembly vote in September 2026 demanding institutions abandon the Mercator projection because it visually shrinks Africa (confirmed real via WebSearch, not assumed); **Positron** as the default basemap style; `attribution` embedded in every PMTiles archive's own metadata (not wired up separately client-side); the info/legend panel should be collapsible. None of these are implemented in the local test page yet. See `DECISIONS.md` **D11**.

## The technical starting point

- `staccato-spec`'s [`catalog-integration.md` §10](https://github.com/UNopenGIS/staccato-spec/blob/main/spec/catalog-integration.md) already commits to the approach this repo should follow: treat STAC as a source to convert *from*, not as Cartographer's primary discovery model; materialize a TileJSON-shaped, `martin catalog`-compatible representation at ingestion time.
- [`hfu/layers-martin`](https://github.com/hfu/layers-martin) is the concrete precedent to study and structurally mirror: it statically generates a Martin-compatible `/catalog` (source list) and `/{sourceID}` (TileJSON) from GSI's `layers.txt`, hosted on GitHub Pages, referencing existing tile URLs rather than duplicating tile data. Read its README and code before designing this repo's STAC equivalent — the goal is the same output shape (`/catalog` + `/{sourceID}` TileJSON), different input (STAC Collections/Items instead of `layers.txt`).
- FERSPAS's STAC assets are, uniformly as far as sampled, COGs (Cloud-Optimized GeoTIFFs) fronted by FAO's own WMTS wrapper — see the 2026-09-03 findings above and `DECISIONS.md` **D2**. This is now measured, not speculative: don't re-derive it from scratch, but do re-verify against the specific collection(s) actually chosen, since only one item per sub-catalog was sampled.
